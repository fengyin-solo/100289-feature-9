# 园林绿化养护管理平台

面向城市园林绿化植物的栽植养护、修剪造型、病虫害防治、灌溉施肥与绿地巡查的一体化绿化管理后台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 园林机械保养口径

园林机械模块（`equipment`）在通用台账之外，落地了一条统一的保养判定口径：

- **下次保养日** = 最近一次有效保养日期 + 该机械类型的保养周期；从未保养过的机械
  从购置日期起算。台账与调度看板共用同一份计算结果（`EquipmentService._decorate`）。
- **调度准入**：距下次保养日不足 5 天（含当天）或已超期的机械一律禁排，并返回具体
  缘由；已报废机械不参与排班（看板直接剔除）。
- **超龄提示**：使用年限超过所属类型上限的机械不拦调度，但在台账和看板单独提示。
- **分类型阈值**：油锯/绿篱机/割草机/割灌机/吹风机各自配置保养周期与年限上限；
  在「判定标准」页调整后会全量重算已有保养记录和台账保养日。
- **重复保养只认第一回**：同一台机械同一保养日期重复登记时，后到记录标记作废并
  说明原因，下次保养日仍按首次保养计算。
- **班组权限**：登记/改动保养记录必须是该机械所属班组的管理员，跨班组或非管理员
  一律拦下（接口通过请求体里的 `操作人/角色/班组` 透传身份，前端页面右上角可切换
  演示身份）。

相关接口：`GET /api/equipment/dispatch-board`（调度看板）、
`GET|POST /api/equipment/maintenance`（保养流水/登记）、
`GET|PUT /api/equipment/types`（类型阈值，PUT 后触发重算）。
